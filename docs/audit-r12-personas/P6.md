## P6-001 — `npm test` glob is unquoted; CI relies on shell `**` expansion that Node 20 + `sh` do not provide. [HIGH / error]

`package.json:41`:

```
"test": "node --test --import tsx src/**/*.test.ts src/__tests__/*.test.ts"
```

CI (`.github/workflows/ci.yml`) pins `node-version: '20'` and runs `npm test`
under Ubuntu's default `sh` (POSIX, no `globstar` by default). In that
environment `src/**/*.test.ts` is passed as a literal string — `node --test`
in v20 does **not** expand glob patterns (glob support was added in v22).
The Phase-9 behavioural tests (`src/__tests__/r10-fg-12-behavioral.test.ts`,
the rewritten `r10-fg-1`/`r10-fg-2`/`r10-fg-3`) live under `src/__tests__/`
which is also matched by the second glob `src/__tests__/*.test.ts` — so
those four happen to run by accident of file location. **But** files like
`src/lib/fencedClaim.test.ts`, `src/lib/orphanReconciler.test.ts`,
`src/custodial/MultiUserAgent.test.ts`, `src/custodial/hcs20-schema.test.ts`,
`src/hedera/contracts.test.ts` are matched only by the first glob and are
silently skipped on any host where `**` is not expanded. The commit message
on 4ba4309 says "747/747 pass" which suggests the developer's local shell
(zsh / bash with globstar) is expanding it, but the CI box may not.

Fix: either pin `actions/setup-node` to v22 AND test that Node's native
`--test` glob picks them up, OR use `tsx --test src/**/*.test.ts` with a
shell that supports globstar, OR (safest) replace with an explicit test
runner directory list, or use `glob` package + `find`-style enumeration.
Recommended: change to `node --test --import tsx --test-name-pattern '.*'
"src/**/*.test.ts"` is wrong too — quotes prevent expansion. The cleanest
fix is to upgrade Node in CI to v22 and rely on `--test` glob, or to use
a globber wrapper script (`scripts/run-tests.mjs` enumerating files with
`glob`).

Verification: temporarily rename one of the source-co-located tests
(e.g. `src/lib/fencedClaim.test.ts`) and re-run `npm test` in CI. If the
count drops, expansion is happening; if it stays the same, those tests
are not running. R10-FG-4 (manifest-vs-tests gate) is structurally
locked, but a regression where the tests aren't *executed* would not be
caught by the manifest gate.

## P6-004 — Deferred items: `pendingLedgerAppliedSet` unbounded growth IS load-bearing for operators on a long-running mainnet. [LOW / quality]

The R11-FG-4 manifest note says the unbounded-growth medium is "DEFERRED
— operational hygiene, not a load-bearing bug, per Phase-9 dissection
§5/§7." That's true for correctness, but for an operator running for
months, the SADD set grows unbounded and `SISMEMBER` cost stays O(1)
but Redis memory cost is O(n_deposits_ever). The DR doc + incident
playbook should at minimum name a TTL knob or a periodic-prune
operator action ("once per quarter, prune entries older than 30 days
via `SREM` for txIds whose deposit timestamp < now - 30d"). Today
neither doc mentions it. This is process-debt, not a bug, but it WILL
bite a long-lived deployment.

R10-FG-6 orphan-reconciler observability: `incident-playbook.md` covers
orphan symptoms (Symptoms 17, 24) and the table at line 1160 is rich,
so this deferred item is genuinely cosmetic — no action needed.

`prize_recovery` decrement: DR doc line 52 lists it as a recoverable
event; verify-audit treats it as not credited per-user (verify-audit.ts:965).
Operator-facing impact is bounded. No action.

## P6-005 — CI workflow does not run `npm run check-protocols` against the deployed URL. [LOW / process]

`.github/workflows/ci.yml` runs `npm test`, `schema:docs:check`, and
`audit:coverage:check`. It does NOT exercise the MCP/A2A parity smoke
test (`npm run check-protocols`). Per CLAUDE.md: "the parity smoke
test verifies this on every release." Today release-time parity
verification is manual. Wire it as a separate workflow job that runs
post-deploy against `testnet-agent.lazysuperheroes.com` (or as a
nightly cron job). Out of scope for this audit but worth flagging
since R11-FG-1's surface (verify-audit consumer wiring) is the kind
of regression a parity test would catch.
