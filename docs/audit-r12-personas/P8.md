## P8-001 — `structural-gate` IS the new placebo escape hatch (HIGH, triage: error)

The R11-FG-2 closure struck `documentation-only` from the enum, but the structural-gate exemption is wider than R10-FG-4's `'individual'` gate. Three holes compound:

1. **Schema:** `audit-coverage-scan.ts:98` declares `tests: z.array(TestRefSchema)` with **no `.min(1)`**. Docstring claims "every entry MUST link at least one test or a structural fixture" — the schema does not enforce it.
2. **Annotation cross-check** (`audit-coverage.test.ts:130`): `if (f.coverageStrategy === 'structural-gate') continue;` — skips the loop entirely.
3. **Placebo gate** (`audit-coverage.test.ts:182`): filters ONLY `coverageStrategy === 'individual' && tests.length === 0`.

**Constructive bypass:** any future entry with `coverageStrategy:'structural-gate'` and `tests:[]` passes every gate vacuously. Same Goodhart escape as R11-FG-2, one label deeper. Five existing entries (R6-FG-1/2/3, R6-Phase-1, R6-Phase-4) currently DO list tests — but nothing forces new ones to.

**Fix shape:** add `.min(1)` to the `tests` Zod array and a dedicated `it()` block asserting that structural-gate entries' linked tests resolve to a real structural fixture file (e.g., `sibling-archetype-gate.test.ts`, `claim-archetype-gate.test.ts`, `audit-coverage.test.ts`).

## P8-003 — R9-FG-12 promotion's revert-proof annotation is at the WRONG site (MEDIUM, triage: quality)

Manifest entry R9-FG-12 links `src/lib/orphanReconciler.test.ts :: 'detects a stale fenced claim under idempotency namespace'`. The actual fix per the manifest summary is the `beforeEach` cleanup candidate list (line 45-54). The linked `it()` block asserts orphan **detection**, not the `beforeEach` cleanup invariant. Reverting the candidate-list fix (removing the `:integration` key) does not flip the assertion in `orphans.length > 0` — it might cause flakiness across test runs in opposite order, but the locking test does not deterministically fail. The annotation comment at line 51-53 acknowledges this: "if the cleanup candidate list regresses, this test becomes **flaky on warm-state runs**." Flaky is not fail-on-revert.

**Fix shape:** add a dedicated test that seeds `${KEY_PREFIX.idempotency}orphan-test:integration` BEFORE `beforeEach`, runs `beforeEach`, and asserts the key was deleted. That's the actual invariant the candidate-list fix locks.
