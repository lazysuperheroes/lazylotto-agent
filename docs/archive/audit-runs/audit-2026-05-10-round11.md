### R11-FG-4 (H) — Phase-8 SADD-before-flush + `withUserLock` interaction can silent-commit a debit without applied-set anchor
**Convergent confirms:** P3-002, P4-003, P4-005, P9-001 — 4 lenses on the same kill-window.
**Site:** `src/custodial/pendingLedger.ts:311-318` (eager) interacting with `src/lib/locks.ts:172-197`.
**Bug:** Phase-8's SADD-before-flush comment claims `updateBalance`'s in-memory mutation is reverted by `withUserLock`'s `refreshUser` at lock-acquire time. But: `refreshUser` runs BEFORE `applyPendingLedgerForUser`, not after a SADD throw. If SADD throws inside the body, `fencedClaim` releases the fence and rethrows; `applyPendingLedgerForUser`'s outer catch swallows; control returns to `withUserLock` which CONTINUES into `await fn()` (the user's withdraw or play). `fn()` runs against the dirty in-memory balance (debit applied, un-flushed), then `withUserLock` calls `await store.flush()` at line 197 — committing the debit to persisted state with NO applied-set anchor. Next drain on a different Lambda: SISMEMBER returns 0, body re-applies → **DOUBLE-DEBIT through a different door**. The behavioral test calls `applyPendingLedgerForUser` directly without simulating `withUserLock`'s post-body flush.
**Why:** This is the same R10-FG-1 archetype (debit + no applied-set anchor → re-apply on next drain) recurring through the SADD-throw branch instead of the kill-mid-await branch the fix was designed for. The comment-vs-code mismatch is pristine: comment names refreshUser as the safety; the production caller doesn't run refreshUser at the claimed time.
**Phase-9 fix:** either move `updateBalance` AFTER the SADD (so a SADD throw aborts before any in-memory mutation), or call `store.refreshUser(entry.userId)` inside `applyPendingLedgerForUser`'s outer catch, or have `withUserLock` re-call refreshUser on `applyPendingLedgerForUser` throw before invoking `fn()`.

## Phase-9 frame recommendation

The dissection doc's hypothesis was: tests catch prior-round archetypes, not current-round introduction archetypes. Phase-8's process change (Section 5a behavioral-test mandate) closed that gap for R10-FG-1..4. R11 reveals **the next gap one layer up: the test asserts the wrong invariant.**

Phase-7's archetype was comment-vs-code. Phase-8's archetype is **assertion-vs-bug** — the behavioral test asserts the *signal* (counter > 0), the *site* (SADD before flush in callLog), or the *symptom* (route doesn't mutate) without asserting the *user-visible invariant* (verify-audit reconstructs correct balance, dashboard never shows phantom funds, double-debit cannot occur via any path).

**Phase-9 process change:**

1. **Test-the-fix-not-the-signal rule.** Every behavioral test for a critical/high finding MUST assert the user-visible invariant the bug broke, not the implementation detail of the fix. Enforced by a code-review checklist + a meta-test that grep'es behavioral tests for `assert.equal(stats.X` patterns and flags them for review.

2. **Consumer-wired gate.** New stats fields, schema fields, or response shapes added in a fix MUST have at least one consumer in the same commit. A grep gate at `npm run consumer-wired-check` walks new field names and asserts they appear in non-test, non-schema files.

3. **Severity-gated `documentation-only`.** Restrict `coverageStrategy:'documentation-only'` to severity `medium` or below. Critical/high entries MUST be `'individual'` or `'structural-gate'` with verified backing test. Zod refinement enforces at parse time.

4. **Ship the Section 5b lockstep gate or strike the section.** No middle ground.

5. **Shared-mock primitive.** Hoist `makeMockRedis(state, opts)` to `src/__tests__/lib/mockRedis.ts`. Every behavioral test imports from there. Cap test fixture LOC per finding at 80 (P12-010).

6. **Storage-back-pressure on the manifest.** Define a retire-entry path: when a structural gate covers a class, the per-finding entries fold into the gate entry and the per-finding tests delete. Otherwise R12 manifest is 50+ entries.

**Phase-9 cluster ordering** (in priority):
- A: R11-FG-1 (wire `refundsDroppedEmptyOriginal` consumer + convert behavioral test to invariant)
- B: R11-FG-3 (cluster-fix dashboard merge-back paths + frontend invariant test)
- C: R11-FG-2 (severity-gated `documentation-only` + Zod refine + retire 9 R9 entries to either individual-with-test or structural-gate)
- D: R11-FG-4 (move updateBalance after SADD OR refresh-on-throw)
- E: R11-FG-5 (discriminated parseRefund nulls)
- F: R11-FG-6 (ship the lockstep gate)
- G: open R10 highs (R10-FG-5..14, R10-FG-16) — at minimum 4 of these per cluster
