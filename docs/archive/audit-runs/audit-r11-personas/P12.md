# P12 — John-Carmack-style functional discipline (R11)

**Branch:** testnet · **HEAD:** f3a0431 (post-Phase-8) · **Stance:** adversarial

Phase-8 closed 4 criticals in 4 commits and added ~1300 lines. Re-reading
those changes by Carmack rules — "do the work in one place, in order, with
the smallest abstraction that earns its keep" — most of the new code is
honest, but several abstractions are scope creep, and one is a rule the
docs claim to enforce that has no enforcement at all.

---

## Findings

### `[ ]` P12-001 (M) — `documentation-only` is now a structural escape hatch, not a waiver

`src/__tests__/audit-coverage.json` distribution after Phase-8:
- `individual`: 10
- `documentation-only`: **9**
- `structural-gate`: 8

R10-FG-4 closed by adding the `tests:[]` gate (good). The mechanical fix
for the 9 offending entries was to flip them to `documentation-only`
(commit 037f5ba: "9 R9-FG entries downgraded individual->documentation-only
with a Phase-8 sweep note; per-finding behavioral tests deferred"). That
isn't closure — it's relabelling. Five of the nine were CRITICAL severity
(R9-FG-1, 2, 3, 6, 11). The strict gate is now defended by a parallel,
unchecked enum value that absorbs every entry that would have failed it.
Same archetype, one rename later.

Carmack rule: remove the escape hatch, don't broaden it. Either (a) require
every CRITICAL/HIGH manifest entry to be `individual` (force the test, or
don't claim closure), or (b) delete `documentation-only` as a value — every
entry must lock at least a structural gate. The current state lets the next
round repeat the placebo via the new label.

### `[ ]` P12-002 (M) — Section 5b "comment->test->code lockstep" has no gate

`docs/audit-cycle-dissection-2026-05-09.md:69-73` declares: "When a fix's
diff includes a code comment containing `must|MUST|NEVER|do NOT|don't`,
the same diff MUST add a test referencing the same finding ID. Enforced
by a pre-merge scan."

Grep the repo: no such pre-merge scan exists. No npm script, no test, no
husky hook, no CI workflow file in `.github/` enforces this. Section 5a
(behavioral-test mandate) has the R10-FG-4 gate test backing it. Section
5b is a process claim with no teeth. The dissection doc treats it as
shipped; it is aspiration. The gap is exactly the comment-vs-code-mismatch
archetype the doc names — claim and reality diverge in the same file that
diagnoses divergence.

Either land a real gate (a `*.test.ts` walking diffs of changed source
files for invariant keywords + paired finding IDs) or strike Section 5b.
Don't ship a process rule whose enforcement is zero.

### `[ ]` P12-003 (L) — `responseBalances` indirection is justified, but the comment block is 2x the code

`app/api/user/status/route.ts:115-167`. The fix is correct: a separate
`responseBalances` variable so `user.balances` stays clean. The
implementation is ~12 lines of executable code. The Phase-8 comment block
documenting the why is 16 lines (lines 107-122). The comment is
load-bearing — it names the bug, names the trade — but pre-Phase-8 a
comment in the same file claimed "we don't mutate the store-cached
object" while the next line did exactly that. Adding a longer comment
doesn't fix the class of failure; it inflates the surface for the next
mismatch.

The structural fix is fine. The 16-line hedge is the kind of comment that
ages poorly: "we used to do X, now we do Y because of R10-FG-2" is
process history, not invariant. Aggressive trim — 4 lines naming the
invariant ("response views are read-only on store-cached objects") — and
delete the historical narrative.

### `[ ]` P12-004 (M) — `refundsDroppedEmptyOriginal: number` records count without sample data

`src/custodial/hcs20-reader.ts:307,653`. The counter increments. Nothing
captures *which* sequence numbers triggered, *which* topic message ID,
*which* originalDepositTxId field shape. In production, an operator who
sees `refundsDroppedEmptyOriginal: 7` knows seven refunds dropped — and
nothing else. To investigate, they must re-walk the topic with a custom
script, since the dispatcher has discarded the offending payloads.

For forensic value, this should be a `{ count: number; samples:
Array<{ sequence: number; refundTxId?: string }> }` with samples capped
at e.g. 10 entries. Same primitive cost (a counter is an array length),
strictly more recoverable signal. The current shape is the cheapest
possible thing that satisfies "categorized stat" without being useful at
incident time.

### `[ ]` P12-005 (M) — `r10-fg-1-behavioral.test.ts` 100+ line `makeMockRedis` duplicates `concurrency-invariants.test.ts`

`src/__tests__/r10-fg-1-behavioral.test.ts:54-160` defines a RedisLike
mock with `sadd/sismember/srem/incr/lrange/lrem/rpush/del/eval/scan/...`.
`src/custodial/concurrency-invariants.test.ts:46-128` defines the
SAME mock for a smaller surface. The two diverge on signature shape
(scan return tuple vs primitive, set value type union) and on broken-mode
flags. Carmack rule: one primitive. Hoist `makeMockRedis(state, opts?)`
into `src/__tests__/lib/mockRedis.ts`, parameterize the broken-mode
flags as `{ saddBroken?: boolean; lremBroken?: boolean }`, share. The
two implementations will drift; one will get a method the other doesn't,
and the next R<N>-FG-* test will copy whichever is closest.

### `[ ]` P12-006 (L) — pendingLedger.ts comment block 30 lines documenting 5 lines of code change

`src/custodial/pendingLedger.ts:281-310`. The SADD-before-flush reorder
is *one statement swap* and a `.catch` removal. The comment block above
it is 30 lines explaining four scenarios (SADD throw, flush throw, LREM
throw, idempotence rationale). Half the comment narrates Phase-7's wrong
ordering — historical context, not current invariant.

The current invariant is: "SADD then flush; on either throw, propagate."
Three lines. The other 27 are the kind of hedge that signals the author
expects to be second-guessed. By P12 rules, hedging in comments is the
opposite of confidence: write the invariant in 3 lines, write a test
that asserts it (already done — `r10-fg-1-behavioral.test.ts`), and
trust the test as the spec. The same pattern recurs at lines 339-355
(busy-branch LREM rationale, ~16 lines for `continue`).

### `[ ]` P12-007 (M) — Behavioral fixtures live in `src/__tests__/` and never get garbage-collected

`r10-fg-{1..4}-behavioral.test.ts` plus the 9 R9-FG-* entries that were
demoted to `documentation-only` mean the manifest carries a permanent
backlog of "deferred behavioral tests". The dissection doc (5a) says
"the tests stay in `src/__tests__/` indefinitely". Coupled with P12-001
(documentation-only as escape hatch), the cumulative state is:
manifest grows monotonically, behavioral tests grow monotonically, and
no audit pass garbage-collects entries when the named bug class is
proved structurally extinct (e.g. by a sibling-archetype gate).

Carmack rule: every entry that exists imposes maintenance cost. Add an
explicit retire-entry path tied to a structural-gate proof — when a
sibling-archetype gate covers the class, the per-finding entries fold
into the gate entry and the per-finding tests delete. Otherwise R11+
manifest will be 50+ entries, R12+ will be 80+, and the gate will be
checking the existence of files nobody reads.

### `[ ]` P12-008 (L) — R10-FG-4 fix could be a Zod refine, not an `it()` block

`src/__tests__/audit-coverage.test.ts:178-193` adds an `it()` block
asserting "every individual-strategy entry has at least one test". The
same constraint is expressible as a Zod refinement on the manifest
schema in `audit-coverage-scan.ts`:

```
.refine(
  (f) => f.coverageStrategy !== 'individual' || f.tests.length > 0,
  { message: '...' }
)
```

The schema-level form fails at parse time (the first manifest load),
not at test time. One source of truth for manifest validity, not two.
The current split means a consumer using the manifest at runtime (not
just the test runner) gets a parse-pass on placebo entries. Move the
gate to the schema; the `it()` block becomes a smoke test that
`loadManifest()` doesn't throw.

### `[ ]` P12-009 (L) — `responseBalances` could be inlined in the `NextResponse.json(...)` call

`app/api/user/status/route.ts:130,166,183`. The variable is assigned
once at line 130 (default = `user.balances`), reassigned at line 166
(adjusted), read at line 183 (response body). Three references, one of
which is the default-fallback. The whole subtraction block could
return the result and be spread inline:

```
const adjusted = computeAdjustedBalances(user, allPending);
return NextResponse.json({ ..., balances: adjusted ?? user.balances, ...});
```

Pure function, no scoped variable, no reassignment, no risk of a future
reader thinking `responseBalances` is something the store should know
about. Minor stylistic call but the post-fix shape still has a mutable
local that the previous version's bug exploited; a pure-function
extraction removes the shape entirely.

### `[ ]` P12-010 (M) — Phase-8 lines-per-bug ratio (~325 LOC/critical) is unsustainable

Phase-8 totals from `git show --stat`:
- 037f5ba: +1277 (R10-FG-4 + dissection doc + previously uncommitted infra)
- b6b7993: +399 (R10-FG-3 + previously uncommitted Phase-7 reader work)
- 45372d3: +387 (R10-FG-2 + behavioral test)
- f3a0431: +725 (R10-FG-1 + previously uncommitted pendingLedger work)

Even excluding the "previously uncommitted" portions, the Phase-8 delta
proper is ~600 LOC of tests + comments + manifest entries for 4 line-level
bug fixes. If R11 finds 4 more criticals — the dissection doc itself
predicts "invariants the author never wrote down" as the next archetype
— Phase-9 will add another ~600 LOC. By Phase-12 the test surface is
4-5kLOC of behavioral fixtures, each one a verbatim mock-Redis copy.

The honest minimum for closing R10-FG-1 was ~5 lines in pendingLedger.ts
plus ~1 test; what shipped was 410 lines of test + 30 lines of comment
+ a manifest entry. That's a 90x ratio of metadata to fix. Sustainable
audits cap that at 5x. Phase-9 should land with a hard cap on
test-fixture LOC per finding (e.g. 80 lines) and a shared mock-Redis
primitive (P12-005); without those, the ratio is monotone and the next
audit cycle's bottleneck is reading the audit, not finding bugs.

## Summary

P12 verdict on Phase-8: the four critical fixes land at the named sites
and the named tests fail-on-revert. But Phase-8 added more abstractions
than the bugs justified: `documentation-only` became a relabel-bypass
(P12-001), Section 5b is a phantom gate (P12-002), the new counter
collects count without samples (P12-004), behavioral test fixtures
duplicate primitives that already exist (P12-005), and comment density
in `pendingLedger.ts` and `route.ts` is hedge-shaped, not
invariant-shaped (P12-003, P12-006). The lines-per-bug ratio (P12-010)
is the meta-finding: at this rate, R12 audits the audit.

Carmack remedy: REMOVE code where possible. Delete
`documentation-only` as a manifest value. Move R10-FG-4 to the schema
(P12-008). Shared mock-Redis primitive (P12-005). Trim invariant
comments to ≤4 lines (P12-003, P12-006). Strike Section 5b OR ship the
gate (P12-002). The remaining real bug-finding work — sample-capture
on `refundsDroppedEmptyOriginal` (P12-004), pure-function extraction
(P12-009), entry retirement (P12-007) — is small.
